# Refine the Specification Before Implementation

When a change affects behavior already governed by a specification:

1. Locate the applicable requirements, design, and task documents.
2. Update the affected specification sections before changing implementation code.
3. Resolve contradictions between the requested behavior and the current specification.
4. Implement and validate the change against the refined specification.

Do not create or update a specification for an unrelated, exploratory, or small maintenance task
unless the user requests it or the project's delivery process requires it.
